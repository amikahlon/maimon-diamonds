# ביצועים, מובייל ונגישות

## תקציב איכות

לכל מכשיר נבחר שילוב של DPR, גודל Environment Cube, מספר שבירות ואפקטים. הורדת משולשים בלבד אינה פותרת עומס שנובע מ־shader או מרזולוציית המסך.

האופטימיזציות הקיימות:

- טעינה עצלה של חבילת Three.js.
- GLB בינארי עם hash במקום Base64 בתוך JavaScript.
- רינדור לפי דרישה דרך R3F.
- עצירת invalidate כשהאובייקט יצא או כשהטאב מוסתר.
- Environment sweep מדורג במקום PMREM בכל פריים.
- DPR מוגבל במובייל.
- Dispose למשאבים זמניים.
- אין React re-render בזמן גלילה.

## מובייל

המובייל משתמש ב־Quality Tier נמוך יותר ובכוריאוגרפיה נפרדת. גודל היהלום במקטע האנטומיה מחושב מה־viewport החי כדי שסרגלי הדפדפן ומסכים קצרים לא ידחפו אותו לתוך הטקסט.

יש לבדוק לפחות 390×844, ‏360×800, מצב Landscape ושינוי Orientation. צילום Headless עם SwiftShader אינו מדד אמין לביצועי GPU של טלפון.

## אבחון טשטוש

Vercel אינו מטשטש WebGL. אם המודל נראה פחות חד בפריסה, יש לבדוק:

1. `devicePixelRatio` ורמת האיכות שנבחרה.
2. גודל drawing buffer ביחס לגודל ה־CSS.
3. האם הדפדפן עבר ל־software rendering.
4. Exposure ו־Environment intensity שעלולים למחוק פרטי חומר.
5. זמן טעינת shader והאם נלכד צילום לפני הפריים המוכן.

## נגישות

- פעולות עסקיות נמצאות ב־HTML סמנטי.
- בחירת מתכת היא קבוצת כפתורים עם `aria-pressed`.
- כפתור 360 מעלות מספק חלופה לגרירה.
- מידע האנטומיה מוצג כטקסט HTML במובייל.
- WebGL failure מדווח דרך `role="status"`.
- האתר מכבד Reduced Motion.

## מדידה

בעת השוואת ביצועים יש לשמור viewport, DPR, מצלמה ותוכן זהים. מומלץ למדוד frame time ולא רק FPS, ולהפריד cold load מגלילה לאחר warmup.
